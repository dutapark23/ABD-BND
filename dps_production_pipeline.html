01 — The System

Step by Step — Session End to Client Inbox

0
During the Session — Set Up for Pipeline Success
This happens before the session even ends. 5 minutes of setup.
0 min effort Pre-session
The pipeline only works if files are captured correctly from the start. Two rules that must be followed in every session:

Rule 1 — Consistent file naming: every session exported as ClientName_EpNumber_YYYYMMDD (e.g. AlZaabi_Ep12_20261005). This makes automation possible — the Make scenario triggers on this naming pattern.

Rule 2 — Record everything simultaneously: DAW captures audio, cameras capture video. Both recordings start at the same time using a clap or timecode. This one action eliminates sync work in post-production.

2 — Video files from the ATEM/cameras — copy SD card files to the session folder. Plug in, copy, done. The camera recorded automatically throughout. 2 minutes.

3 — Upload both to the shared Google Drive session folder. This single upload triggers the Make automation that runs the rest of the pipeline.

04 — The Automation Layer

What Make Does in This Pipeline

DPS already uses Make for the Studio Network. This pipeline adds one new Make scenario that connects the production tools and handles client notification automatically.

1
Trigger: New file uploaded to Google Drive session folder
Make watches the DPS Production Google Drive folder. When a new subfolder appears matching the naming pattern ClientName_EpNumber_Date, the scenario activates. This is the signal that a new session has started the pipeline.
2
Action: Trigger Auphonic API — send audio file for processing
Make passes the WAV file URL to Auphonic's API with the DPS preset (noise reduction + normalisation to -16 LUFS). Auphonic processes and deposits the result back into the folder. Zero human action required.
3
Action: Create client delivery folder with correct permissions
Make creates a dedicated client-accessible Google Drive subfolder, sets view permissions for the client's email address (pulled from Airtable — client records already there from the Studio Network), and prepares the delivery structure.
4
Watch: Monitor for Opus Clip completion signal
Make watches for the Reels files to appear in the folder (named *_reel_1.mp4 through *_reel_5.mp4). This is the last file to arrive, confirming the full package is complete. When all 5 Reels are present, Make triggers the delivery step.
5
Action: Send branded delivery email to client
Make sends a pre-built HTML email from the DPS email address to the client. The email lists all 8 deliverables with direct Google Drive links. Subject line: "Your [show name] Episode [number] is ready 🎙️ — everything's inside." Sent automatically, no human triggers it.
6
Action: Update Airtable session record — status: Delivered
The client's session record in Airtable (already exists from the Studio Network setup) is updated with delivery timestamp, package contents, and status "Delivered." This creates a searchable history of every episode delivered — useful for client reviews, upsells, and the Dubai Podcast Index data.
