Before You Start

What You Are Building & How It All Connects

The Studio Network is a private, invitation-only matchmaking directory for DPS clients. A member browses other creators, requests an introduction, and — if the other party accepts — both receive a direct booking link to DPS. The session gets booked, both get 50 AED credit, and the connection is recorded in their profiles.

You will use four tools. Each has one job:

Tool 01 — Database

Airtable

Stores every member profile, every connection request, and every completed session. The directory members browse is an Airtable view embedded into your Wix site.

airtable.com → free account
Tool 02 — Forms

Tally

Two forms: one for members to create their profile after their session, one for requesting an introduction. Free, no branding, embeds cleanly in Wix.

tally.so → free account
Tool 03 — Automation

Make (formerly Integromat)

The engine that connects everything. When a booking happens in Wix, Make fires a chain of actions: adds to Airtable, sends emails, generates codes. All automatic.

make.com → free account
Tool 04 — Member Portal

Wix Members (already on your site)

The password-protected page where members log in to browse the directory. Already built into your existing Wix subscription — no extra cost, no new platform.

Your existing Wix dashboard

8

Build Form 3 — Accept / Decline Response

10 minutes

This is the simplest form. The recipient receives an email, clicks a link, and lands on this page. Name it: Studio Network — Accept Invitation

  1. Add a text block: "[Requester Name] wants to record a podcast episode with you at Dubai Podcast Studio. Here is what they said: [Episode Idea]. Do you accept?"
  2. Add a hidden field: connection_id (pre-filled via URL)
  3. Add a hidden field: response (pre-filled as either "accepted" or "declined" via two separate links in the email)
  4. Add a hidden field: recipient_email
  5. Add a text block for accepted response: "Thank you — you will receive a booking link within minutes."
Two links, one form: You will create two different URLs for the same form — one with ?response=accepted and one with ?response=declined. Each button in the notification email points to one of these URLs. When submitted, Make reads the hidden response field and fires the correct action.

Build the Studio Network Page in Wix

40 minutes

Inside the Wix editor on your new /studio-network page, add these elements in order:

  1. Header text: "The Studio Network — Members Only" in your brand font
  2. Intro paragraph: "Browse DPS creators available as podcast guests. Find your next episode. Click 'Invite to Record' to send an introduction request — if they accept, you will both receive a DPS booking link and 50 AED studio credit."

Airtable embed and Wix: Some Wix templates block external iframes by default. If the issue persists, use the Wix HTML Embed widget instead of the standard iFrame widget.
11

Set Up the Introduction Request Button with Pre-Filled Parameters

20 minutes

The "Invite to Record" button next to each profile must pass the recipient's name and email to the Tally form automatically. Since the Airtable gallery is embedded as an iframe, the simplest approach is a single shared button that opens a Tally form the user fills manually.

For a more advanced setup where each profile has its own pre-filled link: add a Tally Link field in Airtable (Formula type) with this formula:

-- Airtable Formula field: Tally Link -- "https://tally.so/r/YOUR_FORM_ID?recipient_name=" & ENCODE_URL_COMPONENT({Name}) & "&recipient_email=" & ENCODE_URL_COMPONENT({Email})

This generates a unique Tally link for each member. Show this field in the Airtable gallery view as a button labeled "Invite to Record Together at DPS →". Replace YOUR_FORM_ID with the actual ID from your Tally Form 2 URL.

To find your Tally form ID: Open Form 2 in Tally. The URL will look like tally.so/r/abcXYZ — the ID is the part after /r/.

Building the Automations

Chapter 04

Make — The Five Automation Scenarios

Go to make.com, create a free account, and click + Create a new scenario for each of the five flows below. Each scenario has one trigger and one or more actions.

12

Scenario 1 — New Booking → Airtable + Delayed Invite Email

45 minutes

What it does: When a client completes a booking on Wix, Make adds them to Airtable and schedules the Studio Network invitation email for 24 hours later.

Trigger setup in Wix first:

  1. In your Wix dashboard, go to Automations → + New Automation
  2. Trigger: Booking Confirmed
  3. Action: Send a webhook
  4. In Make, create a new scenario → choose Webhooks → Custom Webhook as the trigger module
  5. Make generates a webhook URL — copy it
  6. Paste the Make webhook URL into the Wix automation webhook field
  7. Save the Wix automation → it will now send booking data to Make on every confirmation

Make scenario — modules in order:

  1. Trigger: Webhooks → Custom Webhook (receives Wix booking data)
  2. Action: Airtable → Create a Record → Table: Members
    • Map Name → Wix booking field: customer name
    • Map Email → Wix booking field: customer email
    • Map Phone → Wix booking field: customer phone
    • Map Session Date → Wix booking field: booking date
    • Map Studio Used → Wix booking field: service/resource name
    • Set Profile Status → Pending (hardcoded)
    • Set Member Since → current date
  3. Action: Tools → Sleep → Duration: 86400 seconds (= 24 hours)
  4. Action: Gmail (or any email module) → Send an Email

Scenario 4 — Introduction Accepted → Send Booking Link + Credit Codes

30 minutes

What it does: When the recipient clicks Accept, Make updates the connection status, generates a unique discount code, and sends both parties the DPS booking link with their credit.

  1. Trigger: Webhooks → Custom Webhook → paste the Tally Form 3 webhook URL
  2. Router module: Split based on the response field
    • Route A: response = accepted → proceed
    • Route B: response = declined → update status to Declined, send a polite decline notification to requester, end scenario
  3. Action (Route A): Airtable → Update Connection Record → Status: Accepted
  4. Action: Tools → Set Variable → generate discount code: NETWORK-{{connection_id}}
  5. Action: Airtable → Update Connection Record → Discount Code: NETWORK-{{connection_id}}
  6. Action: Wix → Create Coupon (via Wix API or manually) for 50 AED — code: NETWORK-{{connection_id}}
  7. Action: Gmail → Send Email to BOTH requester and recipient

Creating Wix coupons via automation: Wix supports coupon creation through its API. This requires generating an API key from your Wix dashboard (Settings → API Keys → Generate Key). Scenario 5 — Discount Code Redeemed → Complete the Connection

20 minutes

What it does: When a NETWORK- code is used in a Wix booking, Make marks the connection as completed and increments both members' session counters.

  1. Trigger: Webhooks → Custom Webhook from Wix (set up a second Wix Automation: trigger = "Booking Confirmed where coupon code starts with NETWORK-")
  2. Action: Airtable → Search Records → Table: Connections → Filter: Discount Code = {{coupon_code_used}}
  3. Action: Airtable → Update Connection Record → Status: Completed, Code Redeemed: checked
  4. Action: Airtable → Search Records → Table: Members → Filter: Email = requester email → Update: Sessions via Network + 1
  5. Action: Airtable → Search Records → Table: Members → Filter: Email = recipient email → Update: Sessions via Network + 1
  6. Action: Gmail → Send Email to both: "Your Studio Network session is confirmed — see you in the studio."
Incrementing a number in Airtable via Make: Make's Airtable module does not auto-increment. Use this workaround: (1) Search for the member record, (2) read the current value of Sessions via Network, (3) in the Update Record step, set the field to {{current_value + 1}} using Make's math function.
Chapter 05

Testing the Full System

Run the complete flow end-to-end before going live. Every step must be verified.

Chapter 05

End-to-End Testing Checklist

Use two test email addresses (e.g. a personal Gmail and a colleague's email) to simulate Member A and Member B. Complete every check before sending the system live to clients.

Phase 1 — New Booking Flow

Make a test booking in Wix using Test Email A. Confirm the booking completes normally.
Check Airtable → a new row should appear in the Members table within 60 seconds. Status should be: Pending.
Check the invitation email arrives at Test Email A after the delay. Verify all variables (name, form link) display correctly.

Phase 2 — Profile Creation Flow

Click the form link in the invitation email. Fill in all fields for Member A including a photo. Submit.
Check Airtable → the Member A row should now show all form data. Status should change to: Active.
Check the welcome email arrives at Test Email A. Verify the directory link works.
Log into the Wix member portal and navigate to /studio-network. Verify the Airtable directory iframe loads and Member A's profile is visible.
Repeat the above for Member B (Test Email B) — make a second test booking, activate their profile.

Phase 3 — Introduction Request Flow

As Member A, click "Invite to Record Together" next to Member B's profile in the directory. Fill and submit the Introduction Request form.
Check Airtable Connections table → a new connection row should appear. Status: Pending.
Check Test Email B receives the notification email with the episode idea message and two buttons: Accept and Decline.
Click Accept. Verify the Tally Form 3 confirmation page loads correctly.
Check Airtable Connections → Status should update to Accepted. Discount Code field should contain NETWORK-[number].
Check both Test Email A and Test Email B receive the introduction confirmed email with the booking link and discount code.

Phase 4 — Booking Completion Flow

Make a test booking in Wix using the discount code from the introduction email. Verify the code applies at checkout.
Check Airtable Connections → Status: Completed. Code Redeemed: checked.
Check Airtable Members → Sessions via Network counter incremented by 1 for both Member A and Member B.
Check both test emails receive the session confirmation email.
All Clear?

If every checkbox above is ticked, the system is working end-to-end. You are ready to launch. If any step fails, go back to the relevant Make scenario and check that all field mappings are correct. The most common issues are: (1) a Tally webhook URL not saved correctly in Make, and (2) an Airtable field name mismatch between what Make sends and what Airtable expects.

Ongoing — What Happens Without Any Action from the Team

Zero ongoing effort

Once the system is live and the seed broadcast is sent, the following happens automatically every week without any staff involvement:

  • Every new Wix booking triggers Scenario 1 → client added to Airtable → invitation email scheduled
  • Every profile form submission triggers Scenario 2 → profile activated → appears in directory
  • Every introduction request triggers Scenarios 3 and 4 → recipient notified → booking link and credit sent automatically
  • Every network booking triggers Scenario 5 → profiles updated → connection marked complete
Weekly Admin — 20 Minutes Maximum

Once per week, open Airtable and check the Members table for any Pending profiles that are more than 7 days old (clients who received the invitation but never completed the form). Send a single WhatsApp follow-up to those clients. That is the full extent of manual work required to run the network.

If You Get Stuck

The three most common points of friction are: (1) Make webhook mapping — if data from Wix or Tally is not reaching Airtable, click "Run once" in Make and check what the webhook receives. The field names must match exactly. (2) Airtable iframe in Wix — if the embed is blank, check that the Airtable share view is set to "Anyone with the link" and that Wix allows external embeds. (3) Hidden fields in Tally — test your URL parameters by pasting the full link into a browser and submitting the form. Check that hidden values appear in Tally's submission log.
